## 1. Goal

Build the "Create with AI" flow in the email area: an AI acting as a professional email marketer interviews the user in phases (Business Profile, Goal, Audience, Call to Action, Sequence and Timing, Reactions, A/B Testing, Draft and Refine, Review and Send), then writes the email or sequence in the business's own voice, sends it through the existing Resend/BullMQ platform, reacts to what each recipient does, and reports results. Jack's direction (2026-10-21): bring the whole spec to life step by step, phase by phase, with screenshots and updates at each milestone.

Business reason: email marketing is the top-tier module in Jack's launch pricing (Complete $99 includes it; Plus $49 excludes it). This is the flagship builder for that tier.

## 3. Build steps

In milestone order. Do not start a later milestone until the earlier one passes its acceptance criteria. At each milestone, post an update on the row BEFORE moving on (screenshots from own running build + What Changed rundown + acceptance-criteria results, Rule 4 standard per milestone).

- Milestone 0 — Audit (THIS BLUEPRINT): audit report (spec §0 areas) + fit-check + this Blueprint, posted on the row. STOP for Jack's go via Kachow. No code yet.
- Milestone 1 — Business Profile (spec Phase 0): BusinessProfile + WritingSample models + API; 3-screen typed profile form (no pick-lists/chips); confirm card every run ("Looks right, continue" / "Edit", 90-day nudge line, required fields block Continue); side-panel edit with mid-flow preservation + profile snapshot per draft; website prefill (server-side fetch, 20s timeout, ≤4 linked pages, SSRF guards, editable "From your website" suggestions, nothing saved until confirmed); My Best Emails (paste or upload .txt/.docx/.pdf, ≤10 samples × 10,000 chars, AI style summary approved/edited before use, samples override voice description, style only never facts, "Save as a good example" once per sent campaign); all Copy in a configurable file, not hard-coded.
- Milestone 2 — Interview engine (Phases 1–3) + Brief confirmation: CampaignDraft model + interview API; phase shell (progress bar, banners, transition recaps, Back with "needs review", escape hatch "Write it with what I have", mic button via browser SpeechRecognition where supported); one-question-per-turn loop with structured Interview JSON (schema validation + repair retry ≤2, checklist base + extra items capped at 6/phase, statuses missing/vague/complete/placeholder, two-attempt rule, question caps 8/phase for 1–3, 24 total); typed Brief confirmation with version locking; cold_contacts flag + list_hints from Phase 2; autosave after every answer, 30-day expiry, resume; blank start every campaign (profile only); automated UI test: no clickable answer options in Phases 1–6; Appendix B conversations B1/B2/B5 as fixtures.
- Milestone 3 — A single email, end to end (Phases 7–8 for one scheduled email): draft generator (3 subject options, preview ≤90 chars, HTML + plain-text bodies, fact_map) + code validator (extract numbers/currency/dates/URLs vs source set; unmapped → removed or {{NEEDS: …}} placeholder blocking send; URL allowlist: profile booking link, profile website domain, user-typed URLs); quality check (≤2 silent revise rounds); refine controls (direct editing, typed instruction box, regenerate whole/section, undo, version history last 10, consistency check); preview (desktop/mobile, plain-text, sample-contact tokens); Phase 8 recipient picker (saved segment, smart list, list, CSV upload with dedupe/validation/rejected rows); AI-suggested filter from list_hints mapped onto existing segment fields (no dedicated filter-builder UI exists — picker offers saved segments/smart lists/CSV; where a hint has no field, say so); exclusion counts; mismatch check (>20% warn); token coverage; automated checks (blocking + warnings incl. SPF/DKIM block, DMARC warn, footer/unsubscribe presence, link HTTP checks); test send + full test sequence with [TEST Email N] prefix + path simulator (7 scenarios); schedule (send now/schedule, weekday 8:00–17:00 business TZ, recommended start); final confirmation with idempotency key; pause/resume/cancel; suppression + locked footer + link tracking (per-recipient token, UTM params, bot filtering: ignore clicks ≤10s after delivery + scanner UAs, store is_bot_suspected).
- Milestone 4 — Sequence and Timing (Phase 4): sequence object (count, span, per-email offsets/purposes, start, deadline, send-time prefs); patterns as AI starting points (not user choices); safeguards (send window, 3/7-day cross-campaign frequency cap, conflict rule skipping contacts in another active sequence, deadline rule with compression, date validation incl. DST); per-person timing from each person's first send; RecipientState tracking; exits (book/reply/unsubscribe stop immediately — reply via InboxMessage poll + manual "mark as replied" endpoint, both already exist).
- Milestone 5 — Reactions (Phase 5): ReactionRule + reaction engine (signals clicked/clicked_link(L)/opened_reliable/open_unknown/not_opened + exits; conditions NOT_OPENED/OPENED_NOT_CLICKED/NOT_CLICKED/CLICKED/CLICKED_LINK(L)/CLICKED_NOT_ACTED; actions send/resend/notify/tag/stop; decision window W default 72h; priority exits > click > NOT_CLICKED/OPENED_NOT_CLICKED > NOT_OPENED; one path at a time; no repeats; caps 8 emails/contact/campaign, 24h gap except click-reaction delay D default 1h; re-check exits + suppression before every send; plain-language readback); owner alerts (in-app Notification + email via existing Resend send); paths view; path simulator matching live behavior; CLICKED_NOT_ACTED + booking metric HIDDEN until booking events exist (see §5 defaults).
- Milestone 6 — A/B testing and results (Phase 6 + §14): ab_test object (one variable: subject or CTA; modes <500 no test / 500–1,999 split 50/50 learning / ≥2,000 test-then-winner 10/10/80; wait default 24h, 4–72 configurable; winner rule ≥20 total clicks + ≥10% relative difference else "no clear winner" → send A; Phase 8 re-check vs real count); Plan confirmation (typed, timeline with branches, version locking); results page (delivered, bounced, unique clicks, click rate, replies, bookings-if-tracked, unsubscribes, complaints, "approximate opens" secondary; paths view; A/B result; plain-language summary from real numbers only); health alerts + auto-pause (warn 0.1% complaint / 2% bounce; auto-pause 0.3% / 5%); code-review check: no results/learnings stored for reuse.
- Milestone 7 — Cold outreach mode: plain-text style 50–100 words, no images; ramp-up caps (20/day days 1–3, 40/day days 4–7, 75/day week 2, 100/day after) with randomized spacing; stop on reply (auto-replies excluded); acknowledgment checkbox (Copy); US business contacts only; separate domain/mailbox required (warn on main domain).

## 5. Build rules

- Reuse first: Resend, BullMQ send worker, MJML compiler, Gemini integration, track endpoints, Resend webhook handler, segments/smart lists, Notification model, InboxMessage reply detection. New tables/services only where nothing exists (per spec §0).
- No new vendor/service without flagging it. Flagged here, in-scope for M1: `mammoth` (.docx parsing) + a PDF text parser (pdf-parse or equivalent) for My Best Emails uploads; server-side sandboxed parsing per spec §20. No other new vendors planned.
- Section 22 defaults — ALL used, recorded here: (1) booking events → click-based logic first; hide booking metric + CLICKED_NOT_ACTED until booking events confirmed. (2) cold outreach requires a separate domain/mailbox; warn otherwise. (3) sequences + reactions in v1 (M4+M5); if scope must shrink, ship M1–M3 first. (4) cold outreach US business contacts only. (5) typed fields only, no chips/dropdowns/pick-lists; business type free text. (6) dictation via browser SpeechRecognition where supported (no platform STT exists); hide button when unsupported. (7) typed confirmations for Brief and Plan; no Approve buttons. (8) A/B thresholds per spec §11. (9) send window weekdays 8:00–17:00 business TZ. (10) frequency cap 3 emails/contact/7 days across campaigns. (11) owner notifications in-app + email via existing notification system (in-app Notification exists; email path wired via existing Resend send in M5). (12) unfinished campaign retention 30 days (autosave; 0 disables resume). (13) model choice configurable; strongest available for interview/drafting, smaller for summaries (Gemini DEFAULT_MODEL pattern already in ai-copilot). (14) interview limits per §5.5. (15) reaction timing: W 72h, D 1h, 8/contact/campaign, 24h gap. (16) no learning from past campaigns (hard rule). (17) machine-open handling: provider flag unavailable → disable OPENED_NOT_CLICKED; keep NOT_OPENED with the Phase 5 caution.
- Typed-only interview: no buttons, chips, dropdowns, option lists or suggested-answer buttons in Phases 1–6. Allowed controls only: Continue, Back, Edit profile, "Write it with what I have", Phase 8 picker + Send controls.
- Nothing carries over between campaigns except the Business Profile. No prefill, suggestions, defaults or learning from earlier campaigns' answers, results, A/B outcomes, send times or edit habits. CampaignDraft data is never read by a new campaign.
- Secrets server-side only (GOOGLE_AI_API_KEY, RESEND_API_KEY never in client or repo). Every query scoped by account_id + cross-account tests. Uploaded/pasted/fetched/CSV content is data, never instructions; rules enforced in code (schema validation, placeholder detection, URL allowlist, number/date checks), never prompt-only. Website fetcher: http/https only, block private IPs/localhost, ≤3 redirects, ≤2MB/page, 20s total timeout. Contact lists and contact-level personal data are NEVER sent to the LLM (v1); previews use sample data.
- Copy (all user-facing text marked "Copy" in the spec) lives in one configurable file, not hard-coded in components.
- Nothing published, sent, or deployed. Builds on branch `agent/create-with-ai-email-campaign-builder` (from main `e1a887e`); pushes are backup only; merges to main only on Jack's approval of the exact thing. Test sends go only to the owner's address(es).
- Baseline before changes: record install/build/test baseline on the branch before M1 code (build + tests currently green on main per M-3 verification; re-run on this branch).

## 6. Acceptance criteria

Per spec §21, plus the row's per-milestone evidence rule:

- M0: audit report posted on the row with blockers + dependencies; fit-check + Blueprint complete; STOP for Jack's go. (This turn.)
- M1: profile entered once, shown every run; required fields block Continue, optional never block; good email with all optional empty and no invented claims; mid-flow edit preserves progress; no pick-lists/dropdowns/chips in profile; prefill never saves unconfirmed; a sample containing a price never leaks that price into a draft.
- M2: banners, progress bar, transition recaps as specified; automated UI test finds zero clickable answer options in Phases 1–6; one question per turn, never re-asks profile facts; "Outreach" alone yields follow-ups until specific (B1 ends naming group, area, outcome, problem, "only you" detail, limit); detailed first answer yields at most one follow-up (B5); vague answers get at most two follow-ups then placeholders; thin audience details never block sending; cold_contacts set + confirmed in Phase 2 recap; sessions resume after refresh; new campaign after a completed one opens blank Phase 1 (automated test).
- M3: invented price in model output removed by validator; any placeholder blocks sending; footer + unsubscribe link unremovable; test send arrives, clicks recorded, duplicate sends prevented.
- M4: book/reply/unsubscribe stops all further emails; frequency cap + conflict rule enforced; no email after deadline; DST test passes; timing measured per person from first send.
- M5: non-clickers get follow-up, clickers get reaction email; one path at a time; no email twice to same contact; machine opens never trigger OPENED_NOT_CLICKED or NOT_OPENED; bot clicks ignored in tests; CLICKED_NOT_ACTED hidden while booking events unavailable; caps (8/contact, 24h gap) enforced; path simulator matches live behavior.
- M6: mode selection by list size incl. "no clear winner" path; Phase 8 re-checks mode vs real count; summary uses real numbers only; auto-pause triggers at thresholds in simulated test; code review confirms no results/learnings stored for reuse.
- M7: daily cap + ramp enforced; reply stops sequence, auto-reply does not; main-domain warning appears.
- Every milestone: row update with screenshots (Inbox Dark, own running build) + What Changed rundown + acceptance-criteria results BEFORE the next milestone starts; if evidence is not relevant or cannot be captured, say so explicitly.
